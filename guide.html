SETUP GUIDE

CARD PORT — 個人用・かんたん説明書

今回はこれだけです

Firebaseの無料Sparkプランで使います。Firebaseに支払い方法を登録する必要はありません。ショップ内にも決済画面はありません。

  • ログインなしで商品を見る
  • 管理者ログインでカードを追加・編集する
  • カートから注文を保存し、シリアルナンバーを表示する
  • 自分の注文履歴を見る／管理者が注文一覧を見る

在庫は自動で減りません。管理者が注文を確認して、必要に応じて在庫数を編集します。個人用の注文受付として簡単にした構成です。同時に複数人が注文した場合の在庫確保・決済・配送は行いません。

1. Firebaseを作る

  1. Firebaseコンソール ↗を開き、Googleアカウントでログインします。
  2. 「プロジェクトを追加」で新規作成します。Google Analyticsは有効にしなくて構いません。
  3. 料金プランは無料の「Spark」のままにします。「Blazeへアップグレード」や「無料トライアル」は不要です。
  4. プロジェクトIDを控えます。後の公開コマンドで使います。

以前の説明書のBlaze・Cloud Functions・App Checkの手順は、今回は実施しません。すでにBlazeへ変更済みの場合、このファイルへの差し替えだけでは料金プランは戻りません。新しいSparkプロジェクトを作るか、既存サービスへの影響を確認してFirebaseコンソールからプランを変更してください。

2. 保存先とログインを有効にする

  1. 「Firestore Database」からデータベースを作成します。Standardエディション、デフォルトのデータベース、本番環境モードを選びます。地域は東京 asia-northeast1 などを選べます。
  2. 「Authentication」→「ログイン方法」で「メール／パスワード」と「匿名」を有効にします。

匿名認証は、注文した人の履歴をほかの人から分けるために裏側で使います。商品を見るだけなら認証は不要です。電話番号認証、Cloud Functions、Cloud Storageは使いません。

3. 管理者を登録する

  1. Authenticationの「Users」→「ユーザーを追加」で、自分のメールアドレスと新しいパスワードを登録します。
  2. 登録されたユーザーの「UID」をコピーします。
  3. Firestoreの「データ」で admins コレクションを作ります。
  4. ドキュメントIDを、自分のUIDにします。自動IDではありません。
  5. フィールド note（string）に 管理者 と入れて保存します。

これで、そのメールアドレスが管理者になります。旧デモの admin とパスワードは使いません。パスワードはHTMLやGitHubに書かず、自分で保管してください。権限を外すときは admins/そのUID のドキュメントを削除します。

4. 接続設定を貼る

  1. Firebaseの「プロジェクトの設定」→「マイアプリ」で、Webアプリ（</>）を追加します。
  2. 表示された firebaseConfig の値を、ZIP内の public/firebase-config.js に入力します。
export const firebaseConfig = {
  apiKey: 'Firebaseに表示された値',
  authDomain: 'あなたのプロジェクトID.firebaseapp.com',
  projectId: 'あなたのプロジェクトID',
  appId: 'Firebaseに表示された値'
};

この設定値は公開してよいアプリ接続情報です。管理者パスワードや秘密鍵を貼る場所ではありません。App Checkのサイトキーは不要です。

5. GitHub Pagesで公開する

このサイトは GitHub Pages ↗ で表示し、商品・注文・ログインはFirebaseプロジェクト card-port に保存します。支払い方法の登録は不要です。

  1. public フォルダー内のファイルをGitHubリポジトリの一番上にアップロードします。public フォルダー自体を入れず、中の index.html などを入れます。
  2. GitHubのSettings → Pagesで main ブランチの / (root) を公開元にします。
  3. FirebaseのFirestore → ルールに firestore.rules の内容を公開します。
  4. Firestore → インデックス → 自動 → 除外を追加で、コレクションID orders、フィールド createdAt、範囲 コレクショングループを指定し、降順を有効にします。
  5. GitHub Actionsの公開処理が完了したらサイトを再読み込みします。

すでに今回の接続設定を使う場合、Firebaseプロジェクトを新しく作り直す必要はありません。管理者パスワードをGitHubへ入れないでください。

6. カードを入れて注文を試す

  1. 右上の「ログイン」→「管理者としてログイン」を開きます。
  2. 手順3のメールアドレスとパスワードでログインします。
  3. カード名・価格・在庫数を入れて保存します。画像URLは空欄でも構いません。
  4. 商品一覧からカートへ入れ、注文を確定します。支払いは発生しません。
  5. 受付番号が表示され、管理画面の注文一覧にも保存されます。
  6. 必要なら、管理画面の「編集」で在庫数を減らしてください。

自分の画像を使う場合、public/images フォルダーに画像を入れて再公開し、画像URLに https://akacnot.github.io/cardport/images/card.jpg のように指定できます。Cloud Storageへの登録は不要です。利用権限のある画像を使ってください。

注文は1回8種類・各99枚までです。商品一覧は最大500件、注文履歴は最新100件です。古いデモの商品は自動移行されないため、最初は商品0件になります。

同じ注文の通信結果が分からない場合は、画面の「同じ注文の結果を再確認する」を押してください。同じ受付キーを使って重複保存を避けます。

使う前に確認すること

  • 別のブラウザーでも、登録した商品が表示される。
  • 管理者以外では商品を追加・編集できない。
  • 注文をすると受付番号が表示され、再読み込みしても履歴に残る。
  • 管理者の注文一覧に受付内容が表示される。
  • 注文しても在庫は減らないため、必要な場合は手動で更新する。

ゲストの注文履歴はそのブラウザーの匿名ユーザーにひも付きます。閲覧データ削除やログイン・ログアウト後には見られなくなる場合があります。番号を控えてください。管理者側には注文が残ります。名前・住所・カード番号の入力はありません。

公開後は上の項目で動作を確認できます。

困ったとき

「接続設定が未入力」：public/firebase-config.js の YOUR_... を実際の値に置き換え、もう一度公開します。

管理者として入れない：ログインするのはメールアドレスです。Firestoreの admins に、そのユーザーのUIDをドキュメントIDとして登録したか確認します。

注文できない：「匿名」のログイン方法が有効か確認します。Firestoreルールを同梱ファイルから公開済みかも確認します。

注文一覧でインデックスを求められる：公開直後は構築が終わるまで少し待ちます。設定ファイル firestore.indexes.json も同梱しています。

請求先登録を求められる：今回使うのはHosting・Authentication・Firestoreだけです。App Hosting、Functions、StorageやGoogle Cloudの無料トライアルの画面を開いていないか確認してください。

注文受付を止めたい：Firestoreに config コレクション／store ドキュメントを作り、ordersEnabled をbooleanの false にします。再開時は true にします。ドキュメント未作成なら受付できます。

無料枠を超えた：Sparkには利用上限があり、機能が一時的に使えなくなる場合があります。課金プランを有効にしないまま使ってください。
